# notes.md — ส่วนที่ 5: เหตุผลการออกแบบ

## โจทย์ที่ 1: Search Box

**ตัดสินใจ**: คำค้นหา (`_searchQuery`) เป็น **Ephemeral State**

**เหตุผล**: ค่านี้มีความหมายเฉพาะภายในหน้า `HomePage` เท่านั้น ไม่มีหน้าจออื่นในแอป
(เช่น `FavoritesPage`) ต้องรู้หรือใช้ค่าคำค้นหานี้ร่วมด้วยเลย เมื่อออกจากหน้า Home
ค่าคำค้นหาก็ไม่จำเป็นต้องคงอยู่ต่อ จึงใช้ `setState` ภายใน `StatefulWidget` ธรรมดา
ไม่จำเป็นต้องยกระดับไปใช้ Provider เพราะจะเป็นการใช้เครื่องมือหนักเกินความจำเป็น
(over-engineering) สำหรับ state ที่ขอบเขตแคบขนาดนี้

## โจทย์ที่ 2: ปุ่มล้างรายการโปรดทั้งหมด

**การใช้ `context.watch` vs `context.read`**:

- ใช้ `context.watch<FavoritesModel>()` ที่ระดับบนของ `build()` เพื่อให้หน้า
  `FavoritesPage` rebuild ทุกครั้งที่ `FavoritesModel` เปลี่ยนแปลง — จำเป็นเพราะ
  ต้องใช้ `favorites.itemCount` มาเช็คเงื่อนไขว่าจะแสดงปุ่มล้างหรือไม่แบบ real-time
  (ปุ่มต้องหายไปทันทีที่ list ว่างจากการล้างหรือลบทีละชิ้น)

- ใช้ `context.read<FavoritesModel>().clear()` ตอนกดปุ่มยืนยันใน Dialog เพราะเป็น
  คำสั่งที่ยิงครั้งเดียว (fire-once action) ไม่ต้องการให้ widget ตัวนั้นสมัครรับ
  การอัปเดตซ้ำอีก — ถ้าใช้ `.watch` ตรงจุดนี้จะทำให้เกิดการ rebuild โดยไม่จำเป็น

**เงื่อนไขการแสดงปุ่ม**: ใช้ `if (favorites.itemCount > 0)` ครอบ `IconButton`
ใน `actions` ของ `AppBar` เพื่อให้ปุ่มแสดงเฉพาะเมื่อมีรายการโปรดอย่างน้อย 1 รายการ
